# `docs/model/` — deployed model artifacts

JSON files the static explorer (`docs/index.html`) loads to make GP
predictions in the browser. Generated artifacts; **don't edit by hand**.

## Files

| File | What it is |
|---|---|
| `strength.json` | The deployed strength GP: kernel + likelihood + input-transform parameters + the training data (`X_train`, `Y_train`). The JS code in `docs/gp.mjs::initStrengthModel` rebuilds `K_lik`, runs its own Cholesky, and solves for `α` at page-load time, reproducing Python's `model.posterior(...)` predictions to FP-summation order. Schema: `schema_version=3`, time-gated multi-Matern kernel with a **Hamming categorical source kernel** (`matern_specific.source_kernel_kind="hamming"`, `source_correlation`) for the 3 material classes, 7 engineered features (`F5_ALLLOG_FEATURES`), max-scale Y normalization. Deployed hyperparameters are block-LOO-refined (see `experiments/regenerate_strength_json.py`). |
| `strength_model.py` | Python `state_dict` snapshot of the deployed `SingleTaskGP`. `boxcrete.load_pretrained_strength_gp()` rehydrates the full model from this without re-fitting. |
| `test_vectors.json` | 37 golden test cases with Python-reference expected values (`expected_mean`, `expected_variance`). `test/test_js_gp.mjs` uses these to verify the JS port computes the same posterior as Python from the same `strength.json`. |
| `compositions.json` | Composition catalog shown in the explorer's mix table, plus precomputed `strength_predictions` at the explorer's display days (1, 7, 28). |
| `gwp.json`, `cost.json` | Sub-model artifacts for the GWP and cost predictors. |
| `slump.json` | The deployed slump GP: ARD RBF kernel + `ConstantMean` + `Standardize` parameters, min-max `Normalize` bounds, and the training data (`X_train` already augmented + normalized, `Y_train` standardized). `docs/slump.mjs::initSlumpModel` rebuilds `K`, factors it, and solves for `α` at page-load time. Schema: `schema_version=1`, `kernel_kind="rbf_ard"`, `outputscale=1` (BoTorch's `SingleTaskGP` default has no `ScaleKernel`). Trained on only **61** observations from Material Source 1 and 2 — mortar (class 0) has no slump data, since its workability is measured with a flow table rather than a slump cone, hence `supported_source_classes`. The 10th input dim is the HRWR/binder ratio with a `max(binder, 1.0)` clamp, which differs from the strength model's `binder + 1.0` guard; see the note in `docs/feature_registry.mjs`. |
| `slump_test_vectors.json` | 85 golden slump posteriors in inches with `observation_noise=True` (all 61 training points plus 24 in-hull random probes), from the **same fit** that produced `slump.json`. `test/test_js_slump.mjs` pins the JS port against these at `rtol=1e-6`. Regenerate the pair together. |
| `mix_analyses.json` | **LLM-authored narrative blurbs** (Claude Opus, with full domain context — specific psi values, dataset comparisons, qualitative assessments). NOT regenerated by `experiments/regenerate_all_artifacts.sh`. The fallback template script `docs/generate_mix_analyses.py` produces *objectively less detailed* output and should not be used to refresh this file casually — see the warning at the top of that script. When mixes are added or removed, hand-prompt an LLM with the new composition + the existing `mix_analyses.json` as a style exemplar. |

## Regenerating

Run `bash experiments/regenerate_all_artifacts.sh` after retraining the
V2 strength GP or changing anything that affects the JS port. The
orchestrator re-fits the model once and re-exports `strength.json`,
`test_vectors.json`, and `compositions.json::strength_predictions` from
that single fit, then runs the JS test suite.

`strength.json` and `test_vectors.json` should come from the same fit —
V2 training is non-convex so two runs can converge to slightly
different local optima. The orchestrator handles this; running individual
steps by hand can break it.
